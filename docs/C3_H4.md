# C3 + H4 — клавиатурный плейтест и багфикс, 05.09.2026

Текущие реализованные механики прошли bugfix-pass. Это **не приёмка финального геймплея перед G3**:
A15/B1–B7/E1–E4 ещё не реализованы/не привязаны к арту. H4 остаётся ongoing для следующего прохода.
C3 закрыт на уровне сервиса и изолированного HTTP-стенда; рабочая таблица не заполнялась фейками.

## Как проверяли

Unity 6000.3.22f1, macOS, Boot → START → Exam. Помощник на Swift отправляет настоящие
OS key-down/up, Unity читает их через обычный KeyboardInputService/EmitInputSystem.
Использованы M, удержание/отпускание Space, Q, стрелки, цифры, буквы, Esc.
В финальном прогоне микрофон остановлен режимом QA «Use keyboard meow»: в записи
KeyboardMeowOnly=True и MicrophoneLevel=0. Автоплеер не меняет игровые сущности.

Автоплеер читает ECS-снимки и знает текущую колоду ответов. Это проверка реального
ввода и механик, но **не слепое визуальное прохождение**. Кадры камеры просматривались отдельно.
Для чтения состояния использован сохранённый диагностический greybox; финальный арт пока статичен.
Изолированные граничные тесты, в отличие от игрока, специально задают состояния/время в отдельных контекстах.

## Что исправлено

B‑005–B‑013 и B‑015 в [BUGS.md](BUGS.md): конфликт Space/шейк, порядок утки/взгляда/штрафа,
потеря продления Staring, потеря ответа на звонке, реакции на M после завершения,
перевзвод микрофона после M, битые ответы сервера, offline-cancellation, ресурсы greybox.
Значения DifficultyConfig/SuspicionConfig и контент не менялись.

При настройке теста его ранний вызов до загрузки Exam выбрасывал исключение и включал аварийный
экран шаблона; инструмент исправлен на NOT RUN без остановки игры. Вторичный сбой
TMP DrawUnderlineMesh в ErrorWindow устранён выводом лога без rich text и ограничением
размера до первых 12000 символов (новые записи идут первыми). Отдельный тест настоящего префаба с длинным логом
с разметкой и коротким логом прошёл; error-window.txt сохранён с остальными результатами.
